# 特色功能

LuckyAgent 的定位是长期运行的 Agent runtime，而不是单轮聊天 demo。它把模型、工具、记忆、知识库、消息入口、API 和部署流程放到一套可运维的结构里。

## 1. 统一运行时

LuckyAgent 的多个入口共享同一个 Agent 核心：

| 入口 | 用途 |
|---|---|
| `lh chat` | 本地 REPL 和单轮调试 |
| `lh serve` | HTTP API、WebSocket 和集成入口 |
| `lh qr` | 启动 API，弹出手机扫码用的临时 key 二维码 |
| `lh msg-gateway start` | Telegram、QQ、NapCat、Weixin 等消息入口 |

统一运行时的好处是：本地验证、API 接入、消息机器人和容器部署不需要维护多套逻辑。

主仓库维护公开 Agent 核心及薄的可执行入口；CLI、HTTP 和渠道产品逻辑由 `luckyagent-app` 提供，模型、配置、会话、记忆与 RAG 等组件由 `luckyagent-runtime` 提供。仍可在主仓库运行 `go build -o lh ./cmd/la` 构建完整程序，详见[模块结构](../core-modules.md)。

会话查找、重命名和删除后的记忆清理，以及模型列表过滤和配置更新，共用[独立应用服务模块](../application-services.md)。中立操作位于 `luckyagent-runtime/appservice`，宿主适配位于 `luckyagent-app/appservice`；CLI、HTTP、Telegram/QQ 和 SDK 复用这些操作，启动 Profile 直接使用运行组件的公开包。CLI 会话切换和删除遇到多个相同 ID 前缀时会提示歧义；配置应用失败时会尝试恢复原配置，并明确报告恢复失败。各入口保留原有的输出格式和渠道权限。

## 2. 配置优先的运行模型

核心行为集中在：

```text
${HOME}/.luckyagent/config.json
```

这让源码运行、Docker 开发环境、生产容器和消息网关共享同一套配置模型。

常见配置维度包括：

- provider、api_base、model，以及 `models.endpoints.chat.credential_ref`
- server.addr、CORS、rate limit、日志格式
- Telegram / QQ / NapCat / Weixin 网关
- RAG、memory、embedding
- Cron、Autonomy、工具和 OpenCLI

## 3. 长期记忆系统

LuckyAgent 不只处理眼前一轮对话，也会围绕长期使用维护记忆。

默认运行目录中包含：

```text
memory/
├── 00_Index/
├── 10_Profile/
├── 20_Projects/
├── 30_Sessions/
├── 40_Decisions/
├── 50_Facts/
├── 60_Rules/
├── 70_Trajectories/
└── 90_Archive/
```

适合保存：

- 用户偏好
- 项目背景
- 决策记录
- 可复用事实
- 会话轨迹
- 长期任务状态

## 4. RAG 知识库

LuckyAgent 提供 RAG 检索和知识注入能力。

常用命令：

```bash
lh rag index ./docs
lh rag search "deployment"
```

可用于：

- 项目文档问答
- 运维手册检索
- 代码库说明检索
- 私有知识库检索
- 长期上下文增强

## 5. 多平台消息网关

LuckyAgent 当前重点支持：

- Telegram
- QQ Official
- NapCat / OneBot v11 reverse WebSocket
- Weixin iLink Bot API
- OpenClaw Weixin 兼容入口

同一个 Agent 可以接入多个外部入口。消息网关侧会处理平台消息、会话、回复格式、媒体和命令入口，再交给统一 Agent runtime。

## 6. 工具系统与 OpenCLI

LuckyAgent 的工具调用围绕统一 tool service 组织，内置能力包括：

- 文件系统相关工具
- Web 内容抽取
- 搜索和查询
- RAG index/search
- `request_credential` 安全凭据表单。明文只进本地加密库，模型只拿到 `credential_ref`
- `create_ephemeral_credential_tool` 根据凭据引用创建当前会话内的临时 HTTP 工具，带 TTL、审批和响应脱敏
- `create_ephemeral_credential_terminal_tool` 根据凭据引用创建当前会话内的临时 terminal 工具，只向受控子进程环境注入凭据，并对输出脱敏
- memory remember/recall
- cron/autonomy/heartbeat
- terminal/shell 兼容工具
- 多模态处理能力

OpenCLI 可作为外部网页和平台操作入口，适合把真实网站能力接入 Agent。

通用执行能力也可以作为 Go 包嵌入其他程序：`luckyagent-tools` 提供 HITL 审批等待、Skill 匹配、工具调用策略、对话压缩和 DAG 工作流。宿主通过回调提供模型调用、动作执行和会话存储；工作流的 HTTP 适配位于 `luckyagent-api/workflow`。这些组件迁移不新增运行时配置字段，现有审批、工具调用和会话格式保持兼容。主仓库已固定包含这些组件的可下载模块版本；跨仓库开发时也可使用本地模块工作区联调。

独立模块 `luckyagent-plugins` 提供插件包校验、安装快照、版本、marketplace 和信任状态。
公开 Agent 接入命名空间 Skills、命令、继承父权限的 Agent 预设、MCP 和原生工具 Hooks；
app 模块提供 `lh plugin` 管理命令及 HTTP/网关入口。安装变更需重启，支持的
Codex/Claude 清单仅为明确子集。见[插件接入说明](../plugin-module.md)。

## 7. Cron、Autonomy 和后台任务

LuckyAgent 支持把 Agent 从“被动回答”扩展到“长期在线执行”。

典型能力：

- 定时任务
- 后台 worker
- 队列持久化
- 结果通知
- cron 结果接回会话
- autonomy 任务生命周期管理

适合提醒、巡检、定期总结、自动采集和持续处理任务。

## 8. 多 Agent 与 Benchmark

评测命令在 `github.com/yurika0211/luckyagent-app`，用于评估和改进 Agent 能力：

- `cmd/la-cache-bench`：prompt cache
- `cmd/la-memory-bench`：记忆激活
- `cmd/la-context-packer-bench`：上下文打包
- `cmd/la-tool-bench`：工具路由
- `cmd/la-multiagent-bench`：多 Agent 编排
- `cmd/la-rag-bench`、`cmd/la-graph-rag-bench`：检索
- `cmd/la-proactive-bench`：主动行为
- `cmd/la-swe-bench`：软件工程任务

本仓库没有这些命令，只保留 `docs/benchmarks/rag-hybrid-retrieval/REPORT.md` 这份历史结果。

## 9. 部署友好

LuckyAgent 支持：

- 源码运行
- 开发 Docker Compose
- 生产 Docker Compose
- GitHub Releases 发布的预构建二进制包
- systemd 风格长期运行
- 多 profile 网关部署

部署时关键是守住同一个约定：

```text
HOME=/var/lib/luckyagent
config.json -> /var/lib/luckyagent/.luckyagent/config.json
```
