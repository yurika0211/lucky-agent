# 会话存储可靠性

会话历史由 `luckyagent-runtime/session` 保存。Agent、HTTP、WebSocket 和 SDK
共同使用这套存储；会话、长期记忆和 RAG 仍承担各自职责。本次不增加配置字段，
`config.example.json` 无需新增键。

## 历史与备份

保存、追加、外置正文、Roll、恢复和删除共用会话生命周期锁。正常保存只处理尚未持久化
的消息尾部；恢复备份等替换操作强制完整重写，重启后仍保持恢复的消息顺序和内容。

新备份使用 v2 格式并包含所引用的外置正文，可在 live 会话目录丢失后恢复正文。
v1 备份继续兼容；如果旧备份的正文已经丢失，恢复明确报错。GC 先读取当前历史、归档和
全部备份的引用，遇到损坏或不可读的引用文件就停止删除。

JSONL 完整换行记录视为已提交。读取可以跳过最后一条尚未换行、语法不完整且没有计入
已持久化消息数的记录，保留此前完整历史；读取不会改盘。下一次追加修复这段坏尾。
中间损坏、已换行的错误记录或已确认保存的消息缺失仍会返回错误。

## 删除与错误返回

删除成功后，旧会话句柄返回 `session.ErrSessionDeleted`，迟到的回复不能重新创建历史。
应用随后取消本 Agent 的在途调用、HTTP 请求和 WebSocket 排队任务。WebSocket 已接受
的请求绑定原句柄，删除后不会通过同一个 ID 创建替代会话。显式发起的新会话仍可使用
相同 ID；旧句柄不能覆盖它。

文件删除失败会返回错误并保留管理器入口和短期状态，不取消正常运行的调用。多个文件
的删除不是事务，失败前可能已有部分文件被移除。取消只约束本进程持有的调用；外部工具
和模型服务需要响应 context 才能停止工作。

Agent 在模型和工具执行前检查历史读取错误，关键追加和最终保存失败会终止本轮，
不会再触发简单聊天 fallback 或成功结束事件。`Agent.CancelSession(id)` 可以取消
该 Agent 登记的同步、流式和 Loop 调用；它不删除会话。

runtime 提供 `GetMessagesWithError`、`AddProviderMessageWithError`、
`AddMessageWithError`。旧签名仍保留兼容，其调用者无法直接接收错误；对历史完整性有
要求的集成应使用带错误的方法。HTTP 会话历史及工具轨迹区分存储错误与空历史；具体
状态码见 [API 文档](API.md#sessions)。

## 大历史访问

HTTP 修改标题、置顶和项目使用 `SaveMetadata`，只写元数据，不要求加载全部消息。
其他集成也可用它保存工作目录和 Agent 角色；需要提交消息时仍调用 `Save`。
列表读取缓存的占用大小，避免每次遍历会话目录。

冷 JSONL 分页首次校验并统计历史，同时构建最多 8192 个偏移的稀疏索引；后续请求直接
定位到目标页附近。索引不保存正文，文件身份、大小或修改时间变化后重建。旧 Markdown
继续使用有上限的尾部缓存。模型上下文组装和显式完整历史读取仍可能加载全部消息。
同一存储目录不支持多个进程同时写同一会话。
